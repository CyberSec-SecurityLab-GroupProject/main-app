## 1. SQL Injection Attempt (API protected by WAF)

**Goal:** Make sure our WAF is actually blocking bad requests and that we can prove it.

**How it’s detected**
1. WAF blocks the request (HTTP 403).
2. CloudWatch WAF metrics show an increase in `BlockedRequests`.
3. (Optional) API Gateway access logs show the request.

## 2. GuardDuty Finding (Suspicious Activity)

**Goal:** Prove GuardDuty + SNS alerting are working once deployed.

**How it’s detected**
1. GuardDuty creates a finding.
2. EventBridge sends it to SNS (email).
3. Alert shows up in Security inbox.

**Response**
1. Open GuardDuty → Findings → confirm it’s new.
2. Check CloudTrail to see who/what caused it.
3. Save screenshot to `docs/evidence/guardduty-finding.png`.
4. Note in team channel: “GuardDuty alert received at <time>.”

---

## 3. API Rate Limit / Abuse (WAF)

**Goal:** Show WAF can slow/block a noisy client.

**How it’s detected**
1. WAF RateLimit rule triggers.
2. CloudWatch WAF metrics show spike in `BlockedRequests`.

**Response**
1. Go to WAF → Web ACL → Requests → confirm source IP.
2. If malicious, add to block list / tell team.
3. Save screenshot to `docs/evidence/waf-ratelimit.png`.
